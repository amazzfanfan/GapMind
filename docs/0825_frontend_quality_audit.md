## 3. 分级问题与建议

### [P1] 首屏主包偏大

- **位置**：生产构建输出；`KnowledgeGraph` 约 494 KB，主入口约 1.83 MB。
- **影响**：比赛现场首次打开或网络不稳定时，Chat/Discover 首次可交互时间可能变长；当前构建给出 Vite 大 chunk 警告。
- **建议**：把知识图谱、KaTeX/重型查看器和不在首屏的页面继续拆为路由级 `dynamic import()`；设置性能预算，例如主入口 gzip 后不超过 350–450 KB，并在 Demo 冻结环境保存一次真实加载时间。
- **优先级**：P1；如果比赛只在本机局域网演示，可在 P0 之后处理，但必须保留构建警告说明。

### [P1] React Hook 依赖警告需要在发布前解释或修复

- **位置**：`DashboardPage.tsx`、`DiscoverPage.tsx`、`GapBoardPage.tsx`、`ResearchPlansPage.tsx`、`WorkspacesPage.tsx`。
- **影响**：回调或 `useMemo` 可能捕获旧状态；在切换工作区、刷新 Discover 或重试 Gap Board 时，存在展示数据滞后的潜在风险。
- **建议**：优先把被依赖函数用 `useCallback` 稳定化，再补入依赖数组；如果确有意保持一次性执行，应在代码旁说明原因并增加对应测试，不要简单关闭规则。
- **优先级**：P1；在真实 Demo 中至少覆盖工作区切换、刷新和失败重试。

### [P2] 状态文案仍可进一步集中

- **位置**：`DiscoverPage.tsx`、`ChatAgentRunCard.tsx`、`StatusBadge.tsx`。
- **影响**：相同内部状态在不同页面可能出现不同中文文案，长期会增加交付材料和用户测试时的解释成本。
- **建议**：把 AI 来源、人工状态、核验状态、执行状态、新鲜度状态分别抽成共享的 label/color 映射；页面只消费映射，不重复写判断。

### [P2] 真实小屏与键盘验收证据缺失

- **位置**：全局布局、Chat 抽屉、Discover 列表和 Evidence Passport。
- **影响**：静态检查不能证明 375px 宽度下描述项、长标题、代码文件列表和按钮仍可操作。
- **建议**：在冻结环境按 375×812、768×1024、1440×900 三个视口执行一遍 Demo 路径；记录键盘 Tab 顺序、焦点可见性、横向溢出和错误提示截图。

## 4. 现场验收清单

- [ ] 375px：Chat 输入、历史抽屉、引用/状态提示不横向溢出。
- [ ] 768px：Discover 的证据门、候选列表、Evidence Passport 可完整查看。
- [ ] 1440px：三分钟 Demo 主路径无大片空白、弹窗不遮挡关键状态。
- [ ] 键盘 Tab：输入框、刷新、确认、驳回、下载和关闭按钮均可到达，焦点可见。
- [ ] 加载中、空数据、错误、部分成功、缓存/实时边界均有用户可理解文案。
- [ ] 录屏中至少出现一次“AI 生成/待审阅”“证据状态”“代码未执行”提示，避免评委只看到结果而看不到边界。

## 5. 结论边界

本审计只能证明静态代码、自动化测试和生产构建层面的结果，不能证明真实用户满意度、现场网络下的加载时间、staging 权限隔离或三轮 Demo 稳定性。上述证据仍应进入 `docs/0825_p0_completion_audit.md` 和最终 `submission/06_效果验证报告.md`。

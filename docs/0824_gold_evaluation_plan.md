# GapMind Gold 与效果评测冻结方案

**版本**：v0.1（2026-08-24）
**状态**：已有 5 个 Chat Gold 问题和检索/外部 Gold 文件；12—20 题完整冻结、基线和人工复核尚未完成。

## 1. 评测范围

评测必须分别回答三类问题，不能用一个“准确率”掩盖差异：

1. **证据检索**：系统是否找到正确论文/片段，来源是否属于允许的 `[En]` 证据。
2. **回答 groundedness**：回答中的关键结论是否被证据支持；证据不足时是否拒答或降级。
3. **工作流价值**：用户是否更快找到证据、发现反证、收窄研究机会和形成可审阅草稿。

## 2. 题目配额（目标 16 题）

| 类别 | 数量 | 必须覆盖 |
|---|---:|---|
| 事实/概念问答 | 4 | 定义、方法、限制，需页码/片段 |
| 方法对比/相似工作 | 3 | 相同问题不同方法，避免只看标题 |
| 反证/边界 | 3 | 证据冲突、分布变化、结论不充分 |
| 研究机会核验 | 3 | 支持、反证、外部新颖性、Critic 收窄 |
| 研究计划/代码草稿 | 2 | 人工确认、风险、静态检查，不声称已执行 |
| 拒答/不可用 | 1 | 没有足够证据或服务降级时的正确行为 |
| **合计** | **16** | 其中至少 3 个问题形成完整证据护照 |

允许在 12—20 题之间调整，但最终数字、题目、标准答案和版本必须冻结，不能为了过阈值临时改 Gold。

## 3. 单题字段

```yaml
question_id: chat-gnn-xx

question: ""

required_evidence: []

expected_behavior: supported | insufficient_evidence | degraded

```

## 4. 指标与判定

- 检索：Recall@k、MRR 或 nDCG，按论文级和片段级分别记录。
- 证据：有效 `[En]` 覆盖率、引用一致性、关键主张支持率。
- 拒答：在 `insufficient_evidence` 题上不制造结论、不伪造来源。
- 工作流：完成任务时间、关键证据找到时间、人工修改次数、人工确认前后状态。
- 稳定性：同一冻结输入重复运行，记录成功率、降级率、超时和异常码。

每个指标都要保留分母、题目集合、模型/索引版本和失败样例；不报告只有分子没有分母的“命中数”。

## 5. 人工评审表

| 题号 | 检索正确 | 关键结论支持 | 引用有效 | 拒答合适 | AI 标记清楚 | 评审意见 | 判定 |
|---|---|---|---|---|---|---|---|
| pending | pending | pending | pending | pending | pending |  | pending |

`pending` 不能写成通过；Gold 文件中 `annotation_status: draft` 或空的 `human_verdict` 不能用作生产阈值证明。

## 6. 冻结门槛

- [ ] 资料台账和快照版本已冻结。
- [ ] 12—20 题全部有标准答案、允许来源和预期行为。
- [ ] 至少 3 题有逐条证据片段和人工确认。
- [ ] 已运行 baseline（普通关键词/向量检索）与当前方案，记录同一题集结果。
- [ ] 已完成至少一轮人工盲评，并保存原始表格和修订记录。
- [ ] 评测报告明确区分离线 Gold、真实用户观察和演示缓存结果。

# GapMind 真实用户测试脚本与记录表

**版本**：v0.1（2026-08-24）
**状态**：脚本和记录模板；两名真实目标用户、授权和结果待执行
**目标**：验证产品是否让目标用户更快、更可靠地完成证据驱动科研任务，而不是收集“看起来不错”的泛泛评价。

## 1. 招募与伦理边界

- 用户 A：图机器学习方向研究生或科研助理。
- 用户 B：导师、教师或有研究方向评估经验的科研人员。
- 不记录真实姓名、联系方式或未经同意的研究材料。
- 测试前说明：系统输出可能是 AI 草稿/候选；用户仍负责最终判断；外部服务和录屏需单独征得同意。
- 没有明确授权时，只保留匿名编号、角色、任务结果和脱敏意见。

## 2. 统一任务（每人相同）

### 任务 A：证据驱动问答

给定冻结 workspace 和问题：“某方法的核心假设、优势与已知限制是什么？”要求用户找到一条支持证据和一条限制证据，并指出是否愿意采信。

### 任务 B：研究机会核验

给定一个候选研究空白，要求用户查看支持证据、反证、外部新颖性和 Critic 收窄结果，最后选择确认、编辑、拒绝或延后，并说明理由。

### 任务 C：计划/代码草稿审阅

要求用户从已确认机会生成研究计划或代码草稿，检查证据回链、风险、人工确认状态和静态检查结果；明确哪些内容不能被理解为已执行结果。

## 3. 记录指标

| 用户 | 任务 | 完成时间 | 首次找到关键证据 | 修改次数 | 错误/误解 | 最后判定 | 是否需要帮助 |
|---|---|---:|---:|---:|---|---|---|
| U-A | A/B/C | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |
| U-B | A/B/C | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |

## 4. 访谈问题

1. 你认为系统解决的第一个痛点是什么？
2. 哪一步最难理解或最容易误操作？
3. 你是否能区分来源证据、AI 草稿、人工确认和证据不足？
4. 如果结果为空或降级，你知道下一步怎么做吗？
5. 哪个输出会被你带回真实科研流程？哪些输出不会？
6. 相比你的原有方法，节省了什么时间，增加了什么审阅负担？

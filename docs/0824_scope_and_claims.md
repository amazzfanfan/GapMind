## 一、本轮产品定位

结合当前已有的 GNN 评测集、研究空白棋盘、知识抽取、Discover 和 Workspace Chat，本轮确认采用下面的定位：

> **GapMind 是面向计算机科学—图机器学习/图神经网络研究场景的证据驱动科研创新助手，帮助研究生、科研助理和导师完成文献理解、研究机会核验、可证伪研究计划设计和代码草稿生成。**

## 二、本轮目标用户和核心任务

### 目标用户

1. **研究生/科研助理**：需要快速理解论文、比较方法、识别研究空白和形成研究计划。
2. **导师/教师/科研负责人**：需要审阅候选方向、核验支持与反证、检查计划是否可证伪。

### 三个核心任务

1. **有证据的文献问答**：针对当前 Workspace 资料回答问题，引用真实论文证据；没有证据时明确拒答或请求补充资料。
2. **研究机会核验**：从现有论文、相似工作、反证和外部检索中形成候选，经过 Critic 和 Evidence Gate 后交给用户确认。
3. **研究计划/代码草稿辅助**：根据已确认或待审阅的研究方向生成计划和代码草稿，保留来源、风险、人工确认和“静态检查不代表执行”的状态。

## 三、本轮明确不做或不承诺

以下内容在本轮比赛版本中不作为已完成能力，不进入核心 Demo 主叙事：

| 能力 | 本轮边界 | 对外表述 |
|---|---|---|
| GraphRAG | 当前 Chat 生产链路主要是 dense retrieval + reranker；知识图谱页面不等于 Chat 已使用 GraphRAG | 只能说“具备知识关系/图谱相关模块或后续实验方向” |
| 生产级混合检索 | 尚未完成稳定的 BM25/RRF/dense A/B 和回归证明 | 不说“混合检索已全面上线” |
| 最终生成模型 SFT | 当前需要区分通用生成模型、垂类抽取模型和知识增强能力 | 没有模型卡和对照实验前，不说“生成模型已完成学科微调” |
| 全面多模态 | 当前强项是 PDF 文本、知识抽取和证据回链；图片/表格/复杂公式能力未形成完整证明 | 不说“已具备成熟多模态科研分析” |
| 自动代码执行 | 当前代码生成以静态完整性检查和草稿为主，没有运行验证 | 不说“代码已执行”或“实验已复现” |
| 自动生成科学事实 | 模型输出、候选机会、外部元数据和计划默认都是待审阅内容 | 不把候选、草稿或模型建议写成事实 |
| 多用户商业化 | 当前是单用户/MVP 认证和本地部署基线 | 不说“已支持高校级多租户大规模使用” |
| 真实服务稳定性 | 当前测试主要 mock 外部依赖，S2/LLM/Ollama/Milvus 等尚未完成持续可用性验证 | 不说“真实外部服务已稳定运行” |
| 用户效果 | 当前尚未完成至少两名真实目标用户结构化试用 | 不提前填写用户认可、节省时间或满意度数字 |

- “当前基线自动化验证为后端 469 项测试通过、前端 56 项测试通过、TypeScript 和构建通过。”

## 五、能力状态分类

### A. 工程已实现，但仍需比赛证据

- 论文导入、解析、知识抽取和证据回链；
- Workspace Chat、同步/SSE、上下文预算、来源标记和引用质量门；
- Discover 多阶段 Agent 流程、Critic、Evidence Gate 和 HITL；
- 研究计划、深度研究、代码生成、分析/写作/审稿回复等受控 Agent；
- Gap Board 相关抽取和候选流程；
- 离线评测协议和自动化测试。

### B. 可用于内部/离线 Demo，但不能直接外推

- 当前 GNN Chat Gold 和局部人工评审；
- 当前 mock 外部服务下的测试通过结果；
- 当前本地 Workspace、storage、data 中的开发资料；
- 当前 Discover 的成功路径和部分成功路径；
- 当前静态代码完整性检查。

### C. 实验或待验证

- facet/章节检索增强；
- 远程 Gap extractor fallback；
- 外部 Semantic Scholar 真实查询和部分成功等级；
- 多模态、专业数据分析、章节增强、个性化和混合检索；
- 真实用户效果和高校试点。

## 六、已确认的四个决策

1. **主学科**：计算机科学—图机器学习/图神经网络。
2. **首要用户**：研究生/科研助理 + 导师/教师。
3. **三个核心任务**：证据问答 + 研究机会核验 + 研究计划/代码草稿。
4. **本轮禁止宣称**：GraphRAG、成熟多模态、代码执行、最终生成模型 SFT、多租户规模化和真实用户效果暂列为未验证/后续范围。

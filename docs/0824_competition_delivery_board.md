## 一、看板目的

这个看板用于管理 GapMind 从“审查意见”到“比赛可提交版本”的落地过程。它不替代详细 Todo List，而是提供当前状态、下一步动作、负责人、预计工时、截止时间、依赖和验收证据。

本项目采用单人开发模式，因此看板中的“负责人”默认是用户本人；AI 工具作为受用户指令约束的辅助执行者，负责阅读、分析、方案拆解、文档起草、代码建议、测试执行和结果整理。AI 不自动代表用户做产品方向决策，不自动对外联络，不自动部署、提交或推送。

## 二、单人开发责任边界

### 2.1 用户本人负责的事项

- 最终确定学科垂直方向、目标用户、核心场景和不做范围。
- 决定真实资料、用户反馈、模型服务和外部平台是否可以使用。
- 招募和联系真实用户，取得试用授权、数据授权和反馈授权。
- 判断模型输出、研究机会、标准答案和用户效果是否真实、准确、可对外使用。
- 决定是否接受 AI 的代码/文档修改建议。
- 审查所有可能影响数据、服务、部署、提交包和 Git 历史的操作。
- 明确授权后才进行 commit；push、公开部署和对外提交需要单独授权。

### 2.2 AI 工具可以辅助的事项

- 阅读项目代码、文档、评测结果和日志，整理问题和依赖。
- 将目标拆解为任务、验收标准、测试用例和文档产出物。
- 起草产品定位、用户测试脚本、Gold 标注模板、Demo 脚本、合规声明和提交材料。
- 在用户授权的范围内修改代码或文档，运行测试并汇总结果。
- 检查文档链接、版本号、状态一致性、测试输出和证据缺口。
- 发现风险后暂停并报告，不以“任务完成”为理由掩盖未验证内容。

### 2.3 AI 默认禁止的事项

- 不自行 commit、push、部署或向外部服务发送用户资料。
- 不使用 `git add .`、`git restore .`、硬重置或其他可能覆盖用户工作的操作。
- 不删除或覆盖 `data/`、`storage/`、`deploy/`、根目录入口、比赛 PDF 和其他用户已有脏文件。
- 不把测试通过推断为真实用户认可、外部服务稳定或科学结论正确。
- 不伪造用户、人工 verdict、标准答案、引用、实验结果、模型效果或商业化数据。
- 不把候选机会、代码草稿、模型建议、外部元数据或未经人工确认的计划写成事实。

## 三、状态和优先级

### 状态

- `[ ]` 未开始
- `[~]` 进行中
- `[x]` 已完成，并且已经保存验收证据
- `[!]` 被阻塞，需要用户决策、真实用户、外部服务或其他前置条件
- `[—]` 本轮明确不做，必须记录原因

### 优先级

- `P0`：比赛基本得分、合规、现场稳定性、可复现提交的阻塞项。
- `P1`：显著提升内容质量、产品体验、技术实现、运维或商业化的项目。
- `P2`：有余力再做的技术先进性或长期产品化项目。
- `GATE`：阶段放行条件；未通过时暂停后续阶段。

### 工时说明

下表中的“预计工时”是单人实际专注工作小时，不是自然日。涉及用户沟通、外部服务等待、模型运行、录屏和材料审查时，实际日历时间可能更长。

## 九、单人开发日常工作流

### 开始任务前

1. 查看本看板的当前状态和“下一步”。
2. 执行 `git status --short --branch`，确认用户已有修改。
3. 阅读对应 Todo 条目、相关代码/文档和前置任务证据。
4. 明确本次是“只读分析、文档修改、代码修改、测试还是外部服务验证”。
5. 如果涉及真实资料、外部模型、公开服务、删除/覆盖或 Git 操作，先由用户确认范围。

### 执行任务时

1. 一次只推进一个主任务，不把多个 P0 混成“顺便完成”。
2. 先建立最小产出物，再补充细节和体验。

4. AI 生成内容统一标记为草稿，用户审核后才能进入对外材料。
5. 发现阻塞就标记 `[!]`，写明阻塞原因、需要谁做决定、下一步是什么。

### 任务完成时

1. 按任务验收标准逐项检查。
2. 保存证据，写入证据索引或任务记录。
3. 只更新当前任务状态，不提前勾选后续任务。
4. 运行与风险相称的测试或审查。
5. 汇报“完成内容、未完成内容、验证结果、风险、下一步”，等待用户决定是否继续。

## 十二、看板维护规则

1. 每次只允许一个 P0 任务处于 `[~]`，避免单人开发同时打开过多上下文。
2. P1/P2 可以保持 backlog，不得用“已计划”代替“已完成”。
3. 任何 `[x]` 都必须有证据路径；没有证据就保持 `[~]` 或 `[!]`。
4. 目标日期是计划，不是事实；延期时记录原因，不要悄悄修改历史状态。
5. 真实用户、标准答案、效果数字和合规结论必须由用户本人审核。
6. 如果新增任务，必须说明它属于哪个 P0/P1/P2 目标，以及是否会影响 GATE-0。
7. GATE-0 通过后，除非用户明确调整范围，不再随意改变核心模型、检索链路、Demo 数据和产品定位。

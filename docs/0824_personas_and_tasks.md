## 二、Persona A：研究生/科研助理

### 背景

- 具备机器学习和图学习基础，能够阅读论文，但需要处理大量相邻方法和实验细节。
- 可能知道问题方向，但不一定能快速判断一个想法是否已经被相近术语或不同方法覆盖。
- 需要保留原文证据，不能只接受一段没有引用的总结。

### 主要任务

1. 查询概念、方法假设、损失函数和实验设置；
2. 比较论文中的方法、数据集、基线和指标；
3. 针对研究想法查找支持、相似工作和反证；
4. 将候选想法转成可证伪计划和代码草稿。

### 期望体验

- 不需要先学习 Agent 术语就能提出自然语言问题；
- 一眼看出回答引用了哪篇论文、哪一段内容；
- 证据不足时系统告诉他缺少什么，而不是给出听起来完整的猜测；
- 可以从问答进入研究发现，但启动长期 AgentRun 前必须显式确认；
- 计划和代码显示哪些内容来自论文、哪些是模板建议、哪些是模型生成。

### 不允许系统替代的判断

- 不能把候选研究机会直接写成“新颖”；
- 不能把没有论文支持的模型猜测作为事实；
- 不能伪造引用、实验结果、用户结论或导师意见；
- 不能自动执行代码或将代码静态检查写成实验验证。

### 主要衡量指标

- 找到关键证据所需时间；
- 论文比较完成时间；
- 人工核查引用的时间和次数；
- 计划需要人工修改的字段数量；
- 因为系统拒答/提示证据不足而避免的错误结论数量。

## 三、Persona B：导师/教师

### 背景

- 关注研究方向是否有价值、证据是否充分、实验设计是否可以验证。
- 不希望把时间花在逐篇打开论文寻找原文，而希望快速审阅候选和风险。
- 对“模型说得很像真的”保持警惕，需要清晰的证据和人工确认状态。

### 主要任务

1. 审阅研究机会候选的支持证据、反证和外部核验；
2. 判断是否需要收窄问题、补查资料或拒绝候选；
3. 审阅计划中的假设、数据集、基线、指标、消融、统计检验和风险；
4. 查看学生/科研助理与系统交互后留下的证据和版本。

### 期望体验

- 直接看到候选为什么出现、支持什么、反对什么、还缺什么；
- 能够区分论文证据、外部元数据、研究计划、报告和代码草稿；
- 能够一键进入原文证据或查看页码/段落；
- 对候选执行保留、收窄、拒绝、要求补查或人工确认；
- 导出报告包含生成模型、知识库版本、证据清单和人工决策记录。

### 不允许系统替代的判断

- 不能自动替导师确认研究方向；
- 不能把 Evidence Gate 通过解释成科学结论已经成立；
- 不能把外部检索部分成功解释为完成了新颖性核验；
- 不能将 AI 计划直接变成正式研究事实或无审查地执行代码。

### 主要衡量指标

- 审阅候选所需时间；
- 发现缺失证据、反证或实验风险的数量；
- 计划一次审阅通过率；
- 人工退回和补查次数；
- 对证据来源、AI 状态和不确定性的理解度。

## 四、任务—功能—证据—指标矩阵

| 任务 ID | 用户 | 任务 | 产品路径 | 必须出现的证据 | 成功标准 | 失败边界 |
|---|---|---|---|---|---|---|
| UQ-01 | 研究生/科研助理 | 论文概念和方法问答 | Workspace → Chat | `[En]`、段落/页码、论文版本 | 结论可回到真实来源，表述符合问题范围 | 无证据时拒答或请求资料 |
| UQ-02 | 研究生/科研助理 | 跨论文方法比较 | Chat → 论文来源卡 | 多篇独立论文、比较字段 | 方法差异、数据集、指标和限制分开呈现 | 来源不支持的比较不得输出为事实 |
| OP-01 | 研究生/科研助理 | 研究机会候选生成 | Discover → Opportunity | 支持证据、相似工作、反证 | 输出候选而不是结论，并标出缺口 | 证据不足进入 needs-more-evidence |
| OP-02 | 导师/教师 | 研究机会核验与收窄 | Discover → Critic → Gate → HITL | 外部核验状态、独立全文、Evidence Passport | 可以保留、收窄、拒绝或要求补查 | 外部服务失败不可标为已核验 |
| PL-01 | 研究生/科研助理 | 形成研究计划 | Research Plan Agent | 假设、数据集、基线、指标、证据来源 | 计划可证伪、字段完整、待人工确认 | 模板默认值需标注为建议 |
| PL-02 | 导师/教师 | 审阅研究计划 | Plans → Evidence/Review | 版本、证据、风险、人工决策 | 能定位缺失字段并留下审阅结论 | 未确认计划不能成为正式资产 |
| CD-01 | 研究生/科研助理 | 代码草稿生成 | Code Generation Agent | 计划来源、文件清单、静态检查 | 有入口/依赖/测试/README 等草稿结构 | 不宣称代码已运行 |
| CD-02 | 导师/教师 | 代码/实验可执行性预审 | Agent Artifact → Review | 静态检查、依赖、风险和未执行标识 | 能决定是否人工下载、修改或后续运行 | 不把静态检查当实验结果 |

## 五、用户旅程映射

```text
研究生提出问题
  → 导入或选择脱敏论文
  → Chat 得到有引用回答/证据不足提示
  → 选择“研究机会核验”并显式确认
  → Discover 生成支持/反证/外部核验结果
  → Critic 收窄，导师或研究生人工确认
  → 生成计划/代码草稿
  → 审阅、修订、导出带 provenance 的候选产物
```
